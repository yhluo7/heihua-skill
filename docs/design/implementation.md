# heihua-skill 实施记录

## 已确定的目标

按照本次对话已选定的方向制作可上传 GitHub 的独立 Skill，不创建远程仓库，不接入个人账号。
把中文办公模糊任务转换为有证据依据、有边界、可开工的工作包，而不是猜测上级心理。

## 设计选择

采用指令型 Skill 加按需加载的场景规则和词库。语言判断由宿主模型执行。Python 仅负责词库检索、结构与引用校验、报告展示和安全安装，不宣称脚本能理解任意自然语言。
没有选择独立在线应用，避免引入密钥、数据库和服务部署。没有选择纯黑话替换字典，避免忽略上下文。

## 实施顺序

1. 阅读竞品原始 SKILL.md，记录来源和查阅日期，避免把少问问题误写成原创。
2. 先写 Python 工具的验收测试并记录失败，再实现格式校验、依赖检查、资料引用检查和 Markdown 渲染。
3. 编写 Skill 工作流和 60 条人工编写的情景规则，明确事实、推断和假设的区分。
4. 制作八个全模拟办公案例，包括同一句话的不同上下文以及不能直接执行的边界案例。
5. 实现离线 Demo 展示和安装工具，添加反例测试与人工评估协议。
6. 编写 README 竞品比较和安装说明，运行本地测试，检查离线展示，打包。

## 验收与约束

Python 工具最低版本为 3.10，仅用标准库。核心 Skill 不要求 Python。
正常情况下零至两个澄清问题。高风险事项不能因为少问问题而越权执行。
不把未确认的截止时间、页数、预算、负责人和口头授权写成事实。
不得复制或打包竞品源码。竞品比较仅限已阅读的公开内容，不声称完成性能对测。
Demo 的输出是随仓库提供的合成参考示例。重新展示 Demo 不等于重新调用模型。
不使用真实雇员、客户、聊天记录或用户个人项目数据。

## 已知验证范围

此环境可执行本地 Python 和 Chromium，不能代表 Windows/Codex/Claude 的真实运行验证。
本次没有可用的独立模型评测代理，没有编造无 Skill 对照组或提升百分比。
